## The problem, stated as a user hits it

targ caches the compiled build-tool binary and rebuilds when its inputs change — including any local `replace` target's contents, so editing targ's own source invalidates the cache. `filepath.WalkDir` never follows symlinks, so that contract breaks silently wherever a symlink stands between the walk and the source:

- **The replace target is a symlink** (`replace … => ../targ-link`, the normal way to share one checkout across projects). `os.Stat` follows links so the directory looks present; `WalkDir` yields the link itself and descends no further.
- **A symlinked directory sits inside a hashed tree.** Reported as a non-directory, contents never read. This applies to the module's own files as much as to replace targets, because both go through `collectModuleFiles`.

Either way: you edit source, the hash does not change, targ reruns the previously cached binary, and nothing says so. Every diagnostic instinct blames your own code first.

Measured, not assumed (scratch probe, this session):

| tree | `os.Stat` | `WalkDir` entries |
| --- | --- | --- |
| real directory | ok, `isDir=true` | 3 (`real`, `pkg`, `a.go`) |
| symlink to it | ok, `isDir=true` | **1** (the link) |
| symlinked subdir inside a walked tree | — | reported `dir=false`, never descended |

**#31** is a different problem in the same loop: in release mode the replace target *is* targ's directory inside `GOMODCACHE` — immutable by construction, verified by hash, never mutated in place — and it gets walked and hashed on every invocation to detect a change that cannot happen.

## Design notes

- **Recorded paths stay LOGICAL; only traversal uses resolved paths.** This is the subtlest requirement in the change and an earlier draft got it wrong. The walker must record each file under the path the *caller* would name it by, not its physical location. On macOS `t.TempDir()` lives under `/var`, itself a symlink to `/private/var`, so a walker that resolves its entry point and records what `WalkDir` hands back returns `/private/var/…/a.go` where every existing caller and test expects `/var/…/a.go` — **changing the cache key for trees that contain no symlinks at all**. A Gate A reviewer implemented the earlier design and reproduced exactly this: two pre-existing subtests of `TestReplaceDirFiles_CollectsFilesystemReplaceTargets` failed on path mismatch. The rule: walk `resolved`, but record `logicalRoot + strings.TrimPrefix(walkedPath, resolvedRoot)`. For an ordinary tree `logicalRoot == resolvedRoot` and the transform is the identity, which is what makes "no behaviour change without symlinks" actually true rather than merely claimed.
- **Where cycle detection lives.** `collectModuleFiles` becomes a thin wrapper over a recursive walker carrying a `visited map[string]bool` keyed by **resolved real path** (`filepath.EvalSymlinks`). Before descending into any directory — the root, or a symlinked entry — the walker resolves it and returns immediately if the resolved path is already in the set.
- **Why the visited set keys on the resolved path (corrected — the earlier justification was false).** An earlier draft claimed logical-path keying "would not detect cycles at all", reasoning that `a/link/link/link/…` grows unboundedly. A Gate A reviewer built the walker both ways and ran all three cycle fixtures: **both terminate**, in 0.31s. In this recursive structure `WalkDir` always runs against an already-resolved directory, so the argument handed to each recursive call is reconstructed identically when a cycle wraps rather than growing. The real reasons to key on the resolved path are: (1) it is the correct invariant — the question is "have I already hashed this real directory?", which only the resolved path answers; (2) **diamond dedup** — two different links to one directory hash its contents once rather than twice; (3) it stays correct if the traversal is ever restructured, where logical keying's termination is an accident of the current shape. Cycle termination is still asserted by test, and the guard is still mandatory.
- **Symlinks may point outside the module, and that is the point.** A replace target's whole purpose is to reference a checkout elsewhere on disk, so the walker must not restrict traversal to the module subtree. The cost is that a nested link to a very large tree will be walked; the cycle guard bounds loops but not size. This is accepted — it mirrors what the Go toolchain can reach through the same links — and is called out here so it is a known property rather than a surprise.
- **`entry.IsDir()` is false for symlinks**, which is exactly why the current code misses them. Detection must test `entry.Type()&fs.ModeSymlink != 0` and then resolve; a symlink to a *file* should be read like any other includable file, a symlink to a *directory* recursed into.
- **Existing filters must survive.** `skipIfVendorOrGit` and `isIncludableModuleFile` apply identically to symlinked content — a symlinked `vendor/` is still skipped, a symlinked `.go` file still included.
- **#31's own open question is resolved: plain skip is safe.** The issue offers "skip the walk **or** hash path+version". Skip loses no coverage: `writeIsolatedGoMod` (`:4332-4362`) embeds `dep.Version` in the synthetic go.mod, which `collectModuleFiles(importRoot)` hashes independently at `:2488`. A version change still changes the key with zero contribution from `collectReplaceDirFiles`.
- **#29's unreachable-target branch has a template two lines away.** The loop already hashes a marker rather than erroring when a directory is missing: `TaggedFile{Path: "replace-missing:" + dir}` (`:2602-2607`), commented "Hash the absence so the key still changes when the dir appears." A dangling symlink is the same situation and must adopt that contract — the #37 cycle's regression came from a new path inventing its own error behaviour instead of its sibling's.
- **#30 is an add-on, not a batch member.** It shares no function with the others (same file only) and is included because its value peaks now: it pins file-set-change detection through `collectModuleFiles` at the moment that function is being rewritten.

	// TERMINATED and did useful work. Asserting non-nil alone fails on a correct
	// implementation when a fixture holds only directories and loops — a Gate A
	// reviewer hit exactly that with an earlier draft of this test.

// collectModuleFiles hashes every source file reachable from moduleRoot,
// following symlinks. WalkDir alone does not descend into symlinked
// directories, so a shared checkout referenced through a link would
// contribute nothing to the cache key and edits to it would never trigger a
// rebuild. Traversal is guarded by a visited set keyed on the resolved real
// path, which terminates symlink cycles and also hashes a directory reachable
// by two paths only once.
func collectModuleFiles(moduleRoot string) ([]discover.TaggedFile, error) {
	return collectModuleFilesFrom(moduleRoot, map[string]bool{})
}

And the recursive helper, complete — `logicalRoot` is how the caller names this directory, `resolved` is where it physically lives, and every recorded path is translated back onto `logicalRoot` so path identity is preserved:

```go
// collectModuleFilesFrom walks logicalRoot, following symlinked directories,
// and records each file under the path the caller would name it by rather than
// its physical location. visited holds resolved real paths already walked, so a
// symlink cycle terminates and a directory reachable by two links is hashed
// once.
func collectModuleFilesFrom(
	logicalRoot string,
	visited map[string]bool,
) ([]discover.TaggedFile, error) {
	resolved, err := filepath.EvalSymlinks(logicalRoot)
	if err != nil {
		// Unreachable is not fatal here; the caller decides how to record absence.
		return nil, nil //nolint:nilerr // unreachable target is not an error at this layer
	}

	if visited[resolved] {
		return nil, nil
	}

	visited[resolved] = true

	var files []discover.TaggedFile

	err = filepath.WalkDir(resolved, func(path string, entry os.DirEntry, err error) error {
		if err != nil {
			return fmt.Errorf("walking directory: %w", err)
		}

		// Translate the physical path back onto the caller's logical prefix. For a
		// tree with no symlinks this is the identity, which is what keeps the cache
		// key unchanged for ordinary trees.
		logicalPath := filepath.Join(logicalRoot, strings.TrimPrefix(path, resolved))

		if entry.IsDir() {
			return skipIfVendorOrGit(entry.Name())
		}

		if entry.Type()&fs.ModeSymlink != 0 {
			return appendSymlinkedEntry(&files, logicalPath, path, visited)
		}

		if !isIncludableModuleFile(entry.Name()) {
			return nil
		}

		return appendFile(&files, logicalPath, path)
	})
	if err != nil {
		return nil, fmt.Errorf("walking module directory: %w", err)
	}

	return files, nil
}

// appendSymlinkedEntry resolves a symlinked entry and either recurses into it
// (directory) or reads it (includable file), recording results under the
// logical path the link occupies.
func appendSymlinkedEntry(
	files *[]discover.TaggedFile,
	logicalPath, physicalPath string,
	visited map[string]bool,
) error {
	target, err := filepath.EvalSymlinks(physicalPath)
	if err != nil {
		return nil //nolint:nilerr // a dangling link contributes nothing, like a missing file
	}

	info, err := os.Stat(target)
	if err != nil {
		return nil //nolint:nilerr // same
	}

	if info.IsDir() {
		if skipIfVendorOrGit(filepath.Base(logicalPath)) != nil {
			return nil
		}

		nested, err := collectModuleFilesFrom(logicalPath, visited)
		if err != nil {
			return err
		}

		*files = append(*files, nested...)

		return nil
	}

	if !isIncludableModuleFile(filepath.Base(logicalPath)) {
		return nil
	}

	return appendFile(files, logicalPath, target)
}

// appendFile reads physicalPath and records it under logicalPath.
func appendFile(files *[]discover.TaggedFile, logicalPath, physicalPath string) error {
	//nolint:gosec // build tool reads source files by design
	data, err := os.ReadFile(physicalPath)
	if err != nil {
		return fmt.Errorf("reading file %s: %w", physicalPath, err)
	}

	*files = append(*files, discover.TaggedFile{Path: logicalPath, Content: data})

	return nil
}
```

Notes the implementer must not lose:
- `skipIfVendorOrGit` returns `filepath.SkipDir` (a sentinel) for vendor/.git — it is returned directly from the `IsDir()` branch, and checked with `!= nil` in the symlink branch where returning the sentinel would skip the wrong thing.
- The recursion passes `logicalPath` (the link's own path), not `target`, so nested content is recorded under the link — consistent with the level-1 case.
- Requires `io/fs` and `strings` in the import block; verify both are present.
- Split into three small functions deliberately: `collectModuleFilesFrom` was measured near this repo's cyclomatic ceiling as one function, and the ceiling has already been hit once this week in `internal/core`.

**`collectReplaceDirFiles` requires NO changes for this task — do not touch it.** Two earlier drafts of this plan modified it (first passing `EvalSymlinks(dir)`'s result to the walker, then patching that) and both were wrong: the first reproduced the path-identity regression for every replace target, the second left `resolved` declared-and-unused, which does not compile. The function as it already stands is correct:

- `os.Stat(dir)` **follows symlinks**, so a dangling target fails the stat and takes the existing `replace-missing:` marker branch — verified: `os.stat` on a dangling link raises `FileNotFoundError`. That covers the unreachable case with no new code.
- It already passes `dir` — the *logical* path — to `collectModuleFiles`, which is exactly the contract the rewritten walker needs, since the walker resolves internally and translates recorded paths back onto the root it was given.

A Gate A reviewer confirmed this empirically: with the walker rewrite in place and `collectReplaceDirFiles` **completely untouched**, all eight tests pass, including both exact-path subtests of `TestReplaceDirFiles_CollectsFilesystemReplaceTargets`. Pre-resolving in the caller was never necessary; the whole caller-side change was inert at best.

The lesson generalises for Task 1: when the walker gains the ability to resolve, its callers should get *simpler*, not more careful. Any urge to pre-resolve at a call site is a signal the walker's contract is not being trusted.
